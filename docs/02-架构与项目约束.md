# 02 · 架构与项目约束

> 2026-09-30：版本化任务清单、独立 `.work` 目录、统一资源调度、发布核对和用户确认恢复已接入桌面流程，详见 [18 · 任务隔离与恢复实施结果](18-任务隔离与恢复实施结果.md)。旧执行器只保留兼容与回归用途；并行能力依赖资源槽位、来源占用和发布目标占用。

## 技术方案

Electron 负责桌面运行时；React + TypeScript 实现界面；electron-vite 统一构建主进程、预加载与渲染端；CSS 语义令牌控制主题；Lucide 提供基础图标；Zod 执行边界校验；Vitest 与 Playwright 验证服务和真实 Electron 行为；electron-builder 预留 Windows NSIS 打包。

Vite 使用与 electron-vite 5 兼容的 7.x 系列，不盲目升级至不在其兼容范围的版本。具体版本以 `package-lock.json` 为准。

## 分层和依赖方向

```text
React 页面 → 工作空间状态 → window.cyberHorse（受限契约）
                             ↓
                        预加载白名单
                             ↓
                      主进程 IPC 来源校验
                             ↓
                  配置服务 / 路径检查服务 / 预处理与四步服务

已实现：四步调度 → 工具适配器 → 外部进程
已实现：媒体库服务 → Emby API / 下载服务 / 媒体复合队列 → 四步引擎
已实现：关机服务 → 可替换的 Windows 系统适配器
```

- 渲染端只拥有展示、表单和交互能力，不能导入 Node.js 或直接运行命令。
- 共享契约不依赖 React 或 Electron。IPC 通道常量与校验依赖分开，避免沙箱预加载加载不允许的模块。
- 独立预处理与四步由主进程服务统一调度和互斥，渲染端只投影真实状态。
- 大量文件扫描、哈希、数据库处理不得阻塞主进程；采用异步 I/O、受控并发、工作线程或外部进程。

## 桌面接口

字幕预览新增 `generateSubtitlePreview`（请求 UUID 与已校验字体样式）和 `cancelSubtitlePreview`（请求 UUID）。主进程生成固定 15 秒模拟素材和 ASS，不接受媒体路径、命令或任意字幕脚本；在应用缓存内互斥执行 FFmpeg，限制超时与大小并通过 ffprobe 核对后返回视频字节。渲染端使用仅向媒体来源放行的 Blob 地址播放，返回时释放；此合成预览不进入业务媒体处理工作目录。详细行为和验证见 `11-统一配置与文件同步.md`。

## 安全基线

启用 `sandbox`、`contextIsolation`、`webSecurity`，关闭 `nodeIntegration`。生产页使用 `horse://app` 自定义安全协议，仅允许读取构建后的页面根目录；阻止新窗口及页面导航，默认拒绝权限请求。

生产 CSP 只允许本地脚本；开发模式为 React 热更新放开内联模块，构建产物不保留此例外。媒体播放器的全屏权限仅允许本应用主窗口的可信主页面，子框架、外部来源、自动全屏及其他权限仍拒绝。后续 Emby 图片来源必须经过可信来源校验，不得把远端网页直接加载为有权限的应用界面。

依据：[Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)、[electron-vite 文档](https://electron-vite.org/guide/)。

## 配置与状态生命周期

- 主进程统一拦截窗口 `close` 与应用 `before-quit`，退出确认默认取消，重复请求只展示一个原生确认框。确认后拒绝新的任务启动和恢复操作，等待已受理的文件变更与启动预检落定，再等待所有执行器停止；收尾异常保留窗口并提示，不强制退出。取消确认不停止采样、后台任务或关机计划。
- 任务清单可选 `removalAction` 区分保留与永久删除，兼容已有版本。删除完成后保留内部移除摘要以识别关联下载，但不再显示任务或计入队列；目录未清理、仍活动或仍可恢复时不能隐藏。旧永久删除摘要按已有明确标记兼容，未知历史不推断为删除成功。

- 存储：`app.getPath('userData')/settings.json`；浏览器独立存于 `localStorage` 的 `cyber-horse-preview`。
- 格式版本：`version: 2`。读取版本 1 时保留路径和有效主题，补齐字幕、媒体服务器及隐私封面字段并原子升级；已有版本 2 文件中的旧强调色字段会安全移除。版本 1／2 中的旧 `system` 主题迁移为默认初号机，当前只接受 `light`、`dark`、`eva`、`ironman`；迁移保留其他有效字段并原子写回。未知版本拒绝读取，不静默丢字段。
- 项目默认值：正常启动读取 `config/default-settings.json`，将用户提供的路径、工具、字幕、服务器和封面字段转换为运行配置；初始化缺失或仍为内置全空默认值的配置，已有主题保留。更新默认工具入口时，可在项目文件的 `previousToolPaths` 指明旧值；仅当前保存值与旧值完全一致的工具项会迁移，其他自定义配置和损坏文件不覆盖。项目文件包含用户明确指定的本机值，已加入 Git 忽略；密码初始化到系统安全存储，不进入运行配置 JSON。旧强调色字段保留在默认文件，界面仍使用主题令牌，不提供自定义强调色。
- 无项目默认文件时，内置回退为：路径、服务器地址与用户名、封面路径为空，字幕为 SRT，封面默认可见，主题为初号机（`eva`）。隔离测试不加载本机项目默认文件。打包清单包含项目默认文件和封面资源，实际安装包尚未验证。
- 密码单独存入 `app.getPath('userData')/media-server-credential.bin`，内容由 Electron 系统安全存储加密；配置 JSON 和渲染端均不读取已存明文。安全存储不可用时拒绝保存。
- 写入：先写 `.tmp`，再替换目标；同一进程串行写入，失败返回 UI。
- 读取失败：启动时使用默认值，运行中保留上一次有效值；中文提示、尽可能备份 `settings.invalid-时间戳.json`，相同损坏内容不重复备份。未显式保存前不覆盖原文件，主题切换遇到无效配置时拒绝写入。
- 文件同步：主进程以 500ms 间隔监听固定配置文件状态，兼容外部编辑器的替换保存与 UTF-8 BOM；读写串行化，内容未变化时复用读取结果。窗口关闭时取消监听；预加载提供专用订阅与释放接口，渲染端卸载时取消订阅。
- 草稿同步：外部发生变化的字段覆盖对应草稿，其他未保存字段保留。保存前重新读取文件并合并，底部统一保存各分组；主题独立即时保存，密码仍单独保存。
- 会话日志和关机计划仅会话内；倒计时、队列结束判定与最后复核由主进程负责，关机请求提交时禁止新任务进入；Windows 系统程序使用固定参数，不强制关闭其他应用。隔离桌面测试强制使用关机替身，打包版忽略测试覆盖。任务清单与事件位于已保存下载目录的 `.work/<任务>`，已登记根、完成历史及脱敏工具日志位于 `userData`。四步和媒体库复合任务启动后可发现残留，但不会自动重跑。预处理另存记录到 `userData/preparation`；旧 `userData/pipeline` 记录不自动转换为新任务。
- 测试通过 `CYBER_HORSE_DATA_DIR` 指定隔离目录，已打包应用忽略此覆盖。
- 未取得单实例锁的进程在创建服务前立即退出，避免正常退出期间继续初始化 Chromium 缓存，导致开发版与已运行应用共用配置时出现缓存访问被拒绝；保留主实例缓存、配置与窗口唤回行为。
- 使用 Electron 单实例锁保护同一用户数据目录；第二次启动退出并唤回已有窗口。共享下载根的不同应用配置还通过 `.work/资源占用` 协调 MDC 和传输槽位；GPU 并发由用户决定，不创建或等待 GPU 锁，旧 GPU 记录原样保留且不参与恢复检查；旧占用记录必须经过用户确认与进程核对才能移除。该机制不协调不同下载根的其他应用和手工启动工具。

## 真实处理必须满足的保护

NAS 文件内容只允许在明确的下载阶段下行（包括所选影片必需的旁车下载），下载完成后不再回读原视频。发布、归档、回写、收尾及恢复禁止 NAS 内容哈希、抽样读取和以 NAS 为源二次复制；允许元数据查询和必要协议应答。摘要在本地计算；NAS 通过完整写入、落盘、大小和持久化身份快照确认。无可靠快照的中断或旧任务停止并保留两端，不按大小相同推断成功。文件系统不支持独占硬链接提交时只能从本地重传，禁止退回 NAS 读取。网络状态栏仍显示整机实测值，不承诺下行绝对为零。

1. 拒绝空路径、磁盘根目录、父目录相互覆盖及危险目录。
2. 明确文件清单，不通过字符串拼接生成删除命令。
3. 执行前形成可审查计划；涉及删除时展示受影响文件及不可撤销说明。
4. 四步处理的复制输出先写临时目标，验证成功后提交；复制失败、取消或磁盘满时保留源文件。预处理在同卷独占建立并核对目标路径后移除源路径，未完成项保留源文件。
5. 工具进程使用参数数组、`shell: false`，处理非零退出、超时、输出编码与子进程树取消。
6. 第三方工具路径与版本在服务中检测；文件存在不能作为可运行的唯一证据。
7. 密码与令牌使用系统安全存储，不进入通用 JSON、日志、仓库或渲染端持久存储。

窗口初始保持隐藏；渲染端恢复配置后在绘制前应用主题，再等待一帧完成，通过无参数白名单 `windowReady` 通知主进程。主进程同时等待 Electron 首帧可绘制事件，首次满足条件时才显示窗口，后续通知不干扰最小化；启动中的第二实例不能提前显示半成品窗口。错误边界可通知显示恢复界面，配置读取失败仍沿用已有回退与中文提示。

## UI 与工程约束

全部描述性内容为简体中文。圆角、颜色、字体、间距按视觉文档执行，业务状态与页面视图分离。以能力组件拆分功能，避免继续扩大 `App.tsx`；新独立页面应提取至对应组件目录。

弹窗和公共控件必须遵守 [项目协作约束中的界面规范](../AGENTS.md#界面规范)：业务确认统一复用应用内 `Modal`，下拉等控件复用已有公共组件与语义样式，完整继承当前主题及统一的尺寸、间距、状态和键盘行为。退出、停止、删除、恢复、警告与错误提示均属于业务界面，不得用系统原生消息框或浏览器默认提示框替代。主进程保留操作与校验职责，通过专用白名单 IPC 请求应用内确认；取消、失去界面连接或重复请求均不能绕过确认执行操作。

原生对话框只用于文件／目录及保存选择器、系统授权，或渲染界面不可用时有明确触发条件的最小错误兜底。退出及破坏性确认默认聚焦安全选项，Esc 与关闭仅取消；保持焦点限制、关闭后焦点返回、忙碌互斥和按钮可达。实际界面验证按影响范围执行，不能以服务测试或原生消息框参数检查替代。当前退出确认仍使用原生消息框，属于待整改实现，不视为符合本条规范；此前生命周期章节记录的是现有行为。

环境检测使用独立状态钩子，区分初始、检测中、完成、失败和浏览器不支持。检测中不展示上次结果，按已保存路径快照复检，同一快照的进行中请求复用；配置变化及卸载使旧响应失效并清理等待计时器。界面总等待上限为 8 秒，主进程单项路径读取上限为 5 秒。系统文件读取本身无法强制中止，超时结果不代表路径失效，迟到的读取不能覆盖已经展示的结果。通过已有白名单接口联通，不新增任意执行能力。

保持 TypeScript 严格检查和锁文件；格式遵循 Prettier。新增依赖说明用途，避免为了单个视觉效果引入大型框架。

最低支持窗口 1060 × 760；默认 1480 × 900，支持最大化。正常桌面窗口保持整页固定。性能与路径状态栏属于应用公共框架，在所有页面底部常驻，不随导航卸载；内容区为底栏预留空间，各页底部留白与左右一致。工作台展示独立预处理、后续四步流程、工作目录与文件范围、工具状态和性能；任务和日志仅在“任务队列”页展示；任务按进行中、已完成、未完成分组，运行日志在底部默认收起，任务清单和展开后的日志分别局部滚动。极窄浏览器与高倍缩放允许内容纵向回流。保持无障碍名称、键盘导航、焦点可见、减少动画偏好。正式发布前增加 125%/150% 缩放和高对比度审查。

日常修改按 [项目协作约束](../AGENTS.md#验证与交付) 分级验证：仅检查受影响的页面、状态与调用链，尺寸或滚动变化才检查该页默认、最小和最大化窗口，颜色或主题令牌变化才检查该区域四种主题。兼容要求不等于每次小改动都执行全量桌面回归；发布验收与无法可靠限定影响的大范围修改再扩大覆盖。

## 发布边界

首版提供构建与打包配置：`npm run dist` 生成 Windows NSIS 安装包，`npm run dist:portable` 生成 Windows x64 免安装单文件 EXE，产物位于 `release`。免安装程序仍使用本机用户数据目录，外部媒体工具与模型需单独配置。提供打包命令不代表已完成目标电脑运行、代码签名、安装升级、自动更新、多平台验证或真实业务迁移。初期目标为 Windows x64；其他平台只有代码层面兼容意图，无发布承诺。

免安装命令在 Windows x64 环境复用依赖安装时下载的 `node_modules/electron/dist`，避免再次解压 Electron 后重命名目录时的本机 `EPERM`。2026-09-30 已验证生成未签名 EXE，尚未启动成品或验证目标电脑运行；详见 [05 · 首版验证结果](05-验证结果.md)。

## 媒体库桌面契约

VLC 内嵌播放使用独立白名单 IPC 和独立 Windows 宿主。主进程校验已保存偏好、媒体标识、窗口边界和会话；只向宿主提供本次 `127.0.0.1` 临时视频／字幕地址，不传递 Emby 认证令牌，不暴露任意文件、程序或 URL 打开能力。宿主只加载标准安装位置中检查过架构的 libVLC 3.x；页面切换、取消、崩溃和退出释放进程与地址。实现和验收边界见 [20 · VLC 内嵌播放](20-VLC内嵌播放.md)。

`openMediaLink` 仅接受媒体标识与 `emby` / `javbus` 固定目标；主进程读取已保存配置和必要的服务端详情生成 HTTP/HTTPS 地址，调用系统默认浏览器。不给渲染端暴露通用 `openExternal` 或任意 URL 打开能力。

新增能力独立定义在 `src/shared/media-library.ts`：媒体库/分页/详情/相关媒体/封面与章节图读取、播放启动/停止、收藏、刷新、应用内主题确认删除、下载启动/查询/取消、复合任务快速入队/查询/取消。旧预览与启动接口仍保留供既有调用；媒体库界面使用单次入队接口，服务先登记任务并去重，再在队列执行时读取 Emby 详情和进行文件、工具预检。全部 IPC 参数经严格模式校验与主 frame 来源检查。网络只在 `EmbyClient` 发起，拒绝重定向，密码和令牌不经过预加载；视频流经限时单会话 `horse://app/media-playback` 地址转发，关闭播放即失效；媒体文件操作由 `MediaDownloads` 和 `MediaProcessService` 管理。详见 `15-Emby媒体库.md`。
