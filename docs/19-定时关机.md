# 19 · 定时关机

## 使用方式

左下角“定时关机”提供两种方式，默认选择按时间，不自动开启，不写入配置。

- **按时间倒计时**：1–720 分钟，保留 15、30、60、120 分钟快捷选项。开启后新任务失败会取消关机；到时仍有任务执行、排队、预检或等待用户确认收尾，也取消本次关机。
- **所有任务结束后关机（包含失败）**：覆盖独立预处理、工作台四步、媒体库复合处理和下载；失败、取消视为结束，但必须先完成执行器和文件收尾。队列结束后启动 60 秒倒计时，期间新任务加入则撤回倒计时，等新任务结束后重新计时。

空队列开启全部任务模式时等待下一次任务启动和结束，历史完成或失败记录不会立即触发关机。失败任务中的文件和恢复记录继续保留，不自动恢复、删除或重跑。待用户确认 Emby 同步收尾的任务阻止关机，必须先确认处理。

等待或倒计时期间点击左下角入口取消。关闭应用立即取消尚未提交的计划；重启不恢复计划。关机请求已经向系统提交后，应用不能再取消或启动新的媒体任务。浏览器预览和非 Windows 系统不能开启真实关机。

## 实现与保护

- `src/shared/shutdown.ts` 定义严格模式请求与状态契约，预加载只提供设置、查询和取消三项专用接口；IPC 验证本窗口主 frame、来源和参数数量。
- `ShutdownService` 维护会话内状态机与计时器，不依赖渲染进程倒计时。任务请求开始即保护异步预检窗口，成功入队后记录本次任务，避免短于轮询间隔的失败任务漏判。
- 判定来自各主进程服务的活动状态、排队状态和待确认收尾状态。队列判定不复制整个四步日志；任务完成但执行器仍在收尾时继续等待。
- Windows 适配器使用系统目录下的 `shutdown.exe` 与固定参数数组，禁止 shell 拼接。应用内倒计时结束并再次核对队列后，才提交 `/s /t 0`；不使用强制关闭参数。此选择避免 Windows 非零延时参数隐含强制关闭，依据 [Microsoft shutdown 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/shutdown)。
- 请求失败、系统权限不足或状态读取异常停止计划，不自动重试，不伪报已关机；成功返回仅表示系统接受请求，其他应用仍可能阻止关机。
- 未打包的隔离桌面测试只要设置 `CYBER_HORSE_DATA_DIR` 就强制使用关机替身，测试只在隔离配置目录记录请求，不能触发真实关机；打包版忽略这一覆盖。

## 验证边界

服务测试覆盖倒计时、空队列、排队与执行收尾、快速失败、新任务加入、异步预检、待确认收尾、失败默认取消、取消与退出、重复开启、系统拒绝、无效参数，以及固定可执行文件和参数。桌面脚本 `scripts/desktop-shutdown.mjs` 验证真实 Electron 沙箱、预加载和 IPC、两项失败任务全部结束触发、新任务重置、两种模式取消、重启不恢复计划，捕获初号机、深色、浅色、钢铁侠、最小窗口及最大化截图，并检查系统配色变化和减少动画环境。

真实系统关机只接入请求，开发验收全部使用替身；未进行真实关机、关机权限差异、其他应用阻止关机、安装包或签名验收。
