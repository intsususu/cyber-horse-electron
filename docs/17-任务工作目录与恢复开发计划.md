# 17 · 任务工作目录与恢复开发计划

日期：2026-09-29。状态：**开发中：P0/P1 基础服务已完成，P2 处理服务已实现、待实机验收**。标记、NFO 与字幕旁车校验已接入当前处理链；新的任务内处理器已通过隔离测试，但桌面任务仍使用旧目录布局。尚未启用统一调度、任务发布与跨重启恢复界面。

## 目标与已确认决策

媒体库处理与工作台批量处理可以同时提交，各自使用独立任务目录；支持单步、部分组合及全部流程。处理状态不再依赖带重名编号的文件名传递。异常退出后由用户选择恢复、结束并保留文件、删除或暂不处理，不自动启动外部工具。

- 本文的“预下载目录”固定对应已保存的 `paths.download`；任务根目录为其下的 `.work`，不静默改用预处理目录、系统临时目录或其他下载配置。
- 每次提交形成一个批次目录，批次内每个输入文件有独立子目录。同番号不同版本也必须隔离。
- “任务完成”指本次选择的步骤、产物发布及必要收尾完成，不要求补跑未选步骤。
- 未选 NAS 归档的工作台任务，将结果移回预处理目录；选了归档则传输到 NAS，校验后清理本地。媒体库复合任务回写原 NAS 影片目录。
- 媒体输入、字幕、处理输出及工具支持指定位置的临时媒体文件放在任务目录。工具安装目录、模型、凭据、全局缓存不搬入任务目录，也不承诺第三方工具完全不写自身运行数据。
- 同卷优先移动，跨卷复制校验后再移除来源；不额外保留整套原视频恢复副本。保留完成下一步或重新执行当前步骤所需的最近一份有效输入。
- 任务目录正常完成后清理；历史摘要与发布记录留在应用数据目录，以支持诊断和识别重复提交。
- 采用独立目录不等于无限并行。GPU 处理、MDC 调用和同一 NAS 目标仍受调度与文件占用约束。

该方案是对旧版“禁止工作目录副本、队列仅会话内”的明确调整。旧版行为仍按现有实现描述；本计划完成前不能在界面或文档中声称已支持恢复。

## 入口与任务边界

| 入口                     | 任务目录内的工作                                 | 成功后的去向                                 |
| ------------------------ | ------------------------------------------------ | -------------------------------------------- |
| 工作台单步、组合、全部   | 冻结文件清单，逐文件执行所选步骤                 | 未选归档回预处理目录；选归档发布 NAS         |
| 媒体库中文字幕、视频破解 | 下载、核对原文件、处理、MDC                      | 原 NAS 影片目录，再核对 Emby                 |
| 独立媒体下载             | 下载临时文件、完整性校验                         | 现有下载目标目录；不自动加入四步处理         |
| 提取清理并重命名         | 独立任务记录；提取对象经任务输入区移交预处理目录 | 预处理目录；原下载残留仍只按用户确认清单清理 |

预处理继续保持独立入口、至少 1 GiB 的既有提取门槛和残留删除预览，不暗中并入四步。其跨卷限制在本次首版保持不变；四步任务的输入接管和结果发布可以按校验复制支持跨卷。

“全部文件”在提交前冻结，之后新增下载不加入本批次。所有来源须登记占用；任务自身媒体只能通过任务清单访问，不重新扫描整个 `.work` 决定处理范围。主进程拒绝从通用文件选择、目录选择或四步 IPC 绕过此边界直接提交 `.work` 中的文件。

## 目录、命名与文件归属

### 目录布局

以下是布局示例，不包含本机个人路径：

```text
<已保存下载目录>/.work/
└─ CLUB-494、CLUB-419等8个文件_20260929-183025-123_a7f2c9d1/
   ├─ 任务状态.json
   ├─ 执行事件.jsonl
   ├─ CLUB-494_01/
   │  ├─ 输入/CLUB-494-C.mkv
   │  ├─ 字幕/
   │  ├─ 视频输出/
   │  └─ 刮削输出/
   └─ CLUB-419_02/
      └─ …
```

- 批次显示名取最多前两个可识别番号；超过两个写“等 N 个文件”，N 为总数。未识别番号则显示“未识别番号等 N 个文件”，完整来源在清单中查看。
- 目录名包含本地日期时间、毫秒和短随机标识，独占创建；真正身份使用完整任务 UUID，不从目录名反推任务身份。
- 去除 Windows 非法字符、保留名称、末尾空格和句点；按完整生成路径检查工具可用长度，名称过长缩短展示部分。无法形成可用路径时在接管输入前报错，不依赖未经验证的长路径支持。
- 子文件身份使用独立标识，显示编号仅用于阅读。同番号不同版本分开存储；不把防重编号追加到传给 MDC 的媒体标记后面。
- 任务内按已确认番号及 C/U/UC 状态生成规范文件名。对现有 `-C_1`、`-UC_2` 等保留原名映射；不把真实多段标记误当成重名编号，不猜测无法确认的番号。
- 创建目录前检查保存配置、权限、空间与路径边界；保存配置、只读预览或打开页面不创建任务目录。任务根目录不接受渲染端自由传入。

### 来源接管与结果发布

1. 入队前冻结来源身份、大小、修改时间、所选步骤、关联文件和发布策略，登记占用；到执行时再次复核。排队本身不提前搬走大文件。
2. 首次移动前先持久化接管意图和目标。相同卷采用独占移动；不同卷复制到任务内临时文件，校验成功并记录后再删除对应来源。
3. 每步仅操作本文件子目录，产物验证完成才更新“当前有效文件”。不能仅凭后缀或非空文件跳过未校验步骤。
4. 未归档结果发布到预处理目录。无冲突时保留约定布局；MDC 的演员/番号结构保留。有冲突时给媒体文件夹增加区分标识，文件本身保持标准 C/U/UC 名称，视频及旁车作为一个包处理，不单独给视频加 `_1`。
5. NAS 回写先形成已批准的替换清单和原文件快照。未知文件、多视频歧义、同目录竞争或快照变化停止并要求重新预览；不能因为任务隔离就覆盖其他版本。
6. 最终目标上的 `.partial` 是传输提交所需的短期文件，属于 `.work` 外的明确例外，须登记任务归属。逐文件落盘后回读 SHA-256，与本地已校验产物核对，再发布。该规则将替换新流程中旧版工作台 NAS 仅按大小校验的行为。
7. 全包新文件发布并校验后才清理替换清单中的旧文件及本地来源。新流程不额外生成长期备份目录；原有 `_tmp` 替换实现需在迁移时由统一发布逻辑取代，历史 `_tmp` 不自动接管或删除。
8. 多文件发布不是整批原子事务。每个文件分别记录准备、提交和清理事件；发生部分发布时保留未处理文件，恢复时核对两端后继续，不承诺自动回滚。
9. 只有已发布结果与历史记录均确认后，才能清理对应任务媒体及空目录。批次部分完成时可以清理已成功子项，保留剩余子项与批次清单；全部收尾后才移除批次目录。

## 工具适配与状态标记

| 工具             | 已确认接口                                                                                   | 新适配要求                                                         |
| ---------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| MDC              | `-cli <文件>`，重复 `-C` 覆盖 `common:source_folders`、`common:success_folder`；`--log-dir=` | 单文件输入、每文件独立刮削输出；不修改共享配置，不使用持续托管模式 |
| Whisper 源码入口 | 文件/目录位置参数，`--output_dir`、`--sub_formats`                                           | 指定任务字幕目录；封装器读取实际返回路径；残留字幕先校验再复用     |
| Jasna            | `--input`、`--output`、`--working-directory`                                                 | 输出和临时媒体指定到任务目录；继续显式关闭后处理命令与关机         |
| mkvmerge         | 输入文件参数、`-o`                                                                           | 在任务目录输出新文件，保留音轨与中文字幕，并检查轨道和时长         |
| ffprobe          | 指定输入路径、结构化媒体信息输出                                                             | 只读检查任务输入和产物，不承担流程恢复判断                         |

运行目录保留工具所需的配置/模型解析行为，所有媒体位置传绝对路径；仍使用明确可执行文件、参数数组、`shell: false` 和受控进程树。任务配置不能包含任意命令、可执行文件路径或明文凭据。

每个媒体文件记录番号、原始名称、字幕标记、破解标记及证据来源。命名推断只表示已有标记，不等同于本应用实际执行成功；本次工具结果还需退出码与内容校验。字幕记录区分已有命名标记、独立字幕轨及本次生成字幕，不能误称文件内必然存在可关闭的中文字幕轨。

MDC 接口验证后增加两道校验：

- 输入：将可靠的处理状态映射为当前工具认可的规范名称，禁止把防重后缀放在标记之后。云端水印设置沿用用户配置，不擅自强制改变。
- 输出：视频内容哈希不变、番号对应、要求的 C/U/UC 状态保留，配套 NFO 可解析且包含约定语义，封面存在且有效。云端配置不输出约定标签时报告不兼容，不修改 NFO 伪造成功。角标像素是否正确需用隔离样本目视验证，不能仅凭文件存在声称角标通过。

必须用当前 MDC 做规范名称与重名后缀样本对照，确定 `-U`、`-UC`、`-C` 的具体兼容方式。文档与本机行为不一致时，以本机隔离验证结果更新适配；标记丢失停止发布，保留任务目录供重试。

官方参考：[MDC 命名规则](https://docs.mvdc.top/naming.html)、[MDC 本地配置](https://docs.mvdc.top/client_configuration.html)、[Jasna CLI](https://github.com/Kruk2/jasna/blob/main/docs/en/cli.md)、[mkvmerge](https://mkvtoolnix.download/doc/mkvmerge.html)。Whisper 以所配置源码入口的帮助和实现为准；旧打包入口缺少 `--output_dir` 时应在预检中提示不支持，不把源码入口的能力当作所有版本的能力。

## 持久化契约与任务状态

先在 `src/shared` 定义版本化类型和严格运行时校验，再实现服务和 IPC。拟增加 `task-workspace.ts`，保持预加载使用的通道常量与运行时校验依赖隔离。

清单至少包含以下数据：

| 数据                                                   | 用途                                       |
| ------------------------------------------------------ | ------------------------------------------ |
| 格式版本、任务 UUID、递增修订号、批次/文件标识         | 识别任务与一致性；不依赖显示名称           |
| 来源入口、创建时间、固定步骤、工具版本/能力摘要        | 确认用户授权的操作与后续可执行性           |
| 原始位置、任务内相对路径、文件身份/大小/时间及必要哈希 | 检查移动、替换、外部变化和恢复条件         |
| 文件状态标记及证据、每步开始/完成/校验结果             | 决定继续下一步或重跑当前步骤               |
| 工作根、发布目标、配置快照摘要和服务器身份引用         | 检查目录变更及服务器变化；不保存密码或令牌 |
| 每文件发布意图、目标校验、提交、旧文件及本地清理状态   | 处理中断和重复恢复；防止重复覆盖、误删     |
| 当前进程归属、错误、取消与用户恢复选择                 | 区分仍在运行、被中断、取消及需要人工处理   |

任务目录保存状态快照与有界事件日志；应用数据目录保存任务索引、已登记工作根和完成历史。关键动作先写意图，校验完成后写结果；快照采用临时文件与替换写入，事件追加后刷新落盘。明确以任务事件序列和已校验快照为执行依据，应用索引可重建；两者不一致时核对实际文件，不能任选更新的一份直接执行。

批次状态拟为：等待、运行中、取消中、中断待确认、失败待处理、已取消、待收尾、已完成、已移除。步骤状态拟为：未执行、执行中、待校验、已校验、跳过、失败。界面状态由文件/步骤/发布记录派生，不直接根据目录存在、工具进度 100% 或刷新 HTTP 成功设置“已完成”。

待收尾细分为“待发布核对”“待本地清理”“Emby 待确认”；已完成的媒体处理不因刷新失败重新运行。失败和取消保留最近有效产物，用户可重新选择恢复或结束；不自动进入再次执行循环。

拟提供 `listTasks`、`getTask`、`enqueueTask`、`cancelTask`、`listRecoverableTasks`、`previewTaskRecovery`、`confirmTaskRecovery`、`previewTaskRemoval`、`confirmTaskRemoval` 等专用能力，最终命名在契约实现时统一。恢复/移除确认只接收主进程生成的计划标识和允许的动作；不接收任意目录或命令。恢复预览绑定修订号、文件快照和有效期，确认时重验，过期重新预览。

## 调度与文件占用

通过共享调度器管理工作台、媒体库、下载与预处理任务，替换“媒体库入队即持有全局锁直到整个队列结束”的行为。每个任务持有独立上下文，禁止多个任务共用可变的单例计划和运行状态。

| 资源                       | 初版限制              | 行为                                                     |
| -------------------------- | --------------------- | -------------------------------------------------------- |
| GPU 推理                   | 全局 1 个             | Whisper 与 Jasna 默认互斥；本轮不提供多 GPU 并行配置     |
| MDC                        | 同一工具入口 1 个     | 隔离媒体输出后仍串行，避免共享配置/缓存影响              |
| 封装及大文件校验/传输      | 分别有界，初始各 1 个 | 限制磁盘压力，可与不冲突的下载/GPU 阶段重叠              |
| 下载                       | 沿用最多 3 个         | 复合任务下载占同一额度，活动文件不进入残留清理           |
| 来源文件及相关旁车         | 独占                  | 入队登记；同一文件重复入队返回现有任务或冲突，不重复搬移 |
| 本地发布目录、NAS 影片目录 | 独占                  | 发布前再次核对快照；不同任务不得先后无提示覆盖同一影片   |
| 预处理残留清理             | 与来源接管冲突时等待  | `.work` 永远排除，活动下载和已预约文件跳过               |

统一按固定顺序申请资源，避免循环等待；等待、失败、取消和异常关闭释放对应资源。任务不能在等待用户确认时占住 GPU 或 MDC。批次按文件提供调度机会，媒体库队列或大批量不能永久独占工具；实际步骤仍按字幕与封装、破解、刮削、归档顺序执行。

不冲突的任务可以继续；同一影片的发布冲突必须进入待处理并重新预览，不能仅靠排队把覆盖变成“合法”。同一文件不同步骤的重复请求不在后台自动合并，避免改变用户已冻结的操作。

## 启动恢复、移除与退出

### 启动发现

1. 先完成应用单实例保护与任务管理初始化，再开放新任务启动。
2. 扫描当前下载目录的 `.work` 和应用索引登记的历史工作根。配置变更后不遗忘旧根；离线或不可读标为未确认，不能当成不存在删除索引。
3. 只识别通过版本校验、身份匹配且路径合法的任务。状态文件视为不可信本地数据，拒绝路径穿越、越界、联接目录及清单中的任意命令；陌生文件夹和损坏清单只提供查看、诊断，不自动恢复或删除。
4. 判断旧进程是否仍占用任务；不能仅凭 PID 存在认定归属，需结合启动时间和可核实身份。无法确认时禁止接管和清理，提示用户处理。
5. 在任务队列集中提示可恢复项目。用户未选择前，不启动处理、重试传输或清理；“暂不处理”保留磁盘内容。

### 恢复策略

| 中断位置                         | 恢复动作                                                                   |
| -------------------------------- | -------------------------------------------------------------------------- |
| 入队后尚未接管输入               | 复核冻结来源与配置，重新确认后执行                                         |
| 输入移动或复制过程中             | 核对两端及已写事件，只接管完整且身份正确的一份，避免重复删除               |
| 下载未完成                       | 初版重新下载；不承诺 Range 续传，原 `.download` 的移除须经过任务归属核对   |
| 字幕/破解/封装运行中             | 核对旧进程和输入；未验证工具级断点时重跑当前步骤，不从百分比续算           |
| 工具已退出但未完成记录           | 检查产物并补做完整校验，符合条件才承认为已完成                             |
| 某步骤已校验成功                 | 跳过该步骤，从下一个已选择步骤继续                                         |
| MDC 已移动输入、只生成部分结果   | 在任务范围内定位并核验视频；可恢复的输入重新进入刮削，不能假定原路径仍存在 |
| NAS 部分传输或部分发布           | 对照每文件记录与两端内容，仅补未完成操作；目标外部变化时停止               |
| NAS 完整发布、本地未清理         | 重新确认目标有效，只执行待清理动作，不重新破解或刮削                       |
| 仅剩 Emby 同步                   | 重新定位媒体并核对更新，不重做媒体处理                                     |
| 完成记录已保存、任务目录尚未移除 | 展示可清理残留；确认没有唯一副本和未知文件后仅清理本任务                   |

恢复使用任务创建时的目标和配置摘要。当前工具、模型、目录、服务器身份发生变化时重新预检；不得静默把旧任务输出写到新 NAS 或新服务器。需要换目标时必须生成新的预览。每个恢复动作具备重复执行保护。

### 移除与取消

- “取消”先停止工具和后续调度，保留最近有效文件及状态；取消不等于删除任务目录。
- “结束任务并移回可用文件”是默认移除方式：把未发布的有效文件退回原位置或预处理目录，先展示具体去向；重名按媒体包隔离，不覆盖现有文件。
- 原始视频若已被校验后的新产物替换，不能承诺恢复原版本，应明确保留的是当前有效版本。
- “删除任务文件”是独立动作，预览列出将删除的内容、大小及是否包含唯一副本，用户明确确认后才执行。
- 删除前重新核对绝对路径、任务根与目录身份，只逐项删除本任务清单文件和已知空目录。出现未知文件时停止自动清理；不得递归清空 `.work`、下载根或配置根。
- 正常退出停止新调度并等待文件操作收尾、持久化中断状态；强制退出由下次启动恢复检查处理。Windows 子进程使用可验证的归属与终止机制，不能按同名进程批量结束其他任务。

## Emby 更新与完成条件

媒体处理、NAS 发布、Emby 更新分别记录，避免把“刷新已提交”当成“新视频已入库”。NAS 发布后依据保存的服务器身份、原目录映射和发布文件重新发现媒体；旧项目 ID 只用于参考，不能假定改名后仍对应正确视频。

先通过接口文档及隔离服务器验证目标目录/所属媒体库扫描与查询方式，再接入有限次数、有超时的刷新和回查。确认服务端媒体源路径对应新文件，并核对可用的大小、轨道及元数据信息；服务端缺少字段时不能伪造确认。

超过等待期限显示“媒体已回写，Emby 尚未确认”，进入待收尾；允许只重试同步。此时已发布媒体的本地副本可以在内容核对后清理，但保留任务清单和历史记录；Emby 确认或用户明确结束待收尾后再清除空任务目录。没有配置 Emby 的普通工作台任务不强制增加服务器同步步骤。

## 配置、界面与迁移

- 首版由下载目录派生 `.work`，不增加第二个可任意指定的任务根配置。下载目录为空或不可用时明确报错；不能绕过已保存目录限制。
- 字幕工作、视频工作、MDC 输出的旧配置值保留，不自动迁移或删除里面的文件。新任务实际输出由 `.work` 管理；界面说明旧路径的兼容用途，不能仍把旧目录展示为本次输出。NAS、预处理和工具入口继续使用保存配置。
- 四步下方目录按钮：有运行任务时显示可选任务的实际步骤目录，无任务时打开相应最终目录或说明；不再悄悄打开一个本次未使用的全局目录。
- 工作台和媒体库均可提交，任务和日志只在任务队列展示。队列由统一任务模型驱动，支持多个工作台批次；不再由新批次覆盖旧批次状态。批次父项计数，子文件和下载不重复计数。
- 清空历史只移除可清除的展示记录，不删除文件；有未处理残留的任务不能通过“清空记录”隐藏其恢复入口。
- 恢复与移除弹窗展示来源、步骤、已完成部分、待处理文件、目标和冲突。错误、未确认进度、服务器待确认均使用真实中文状态。
- 新后台未就绪时不启用新按钮；更新主进程必须在任务结束后完整重启，不用页面热更新假装完成迁移。
- 旧版 `pipeline`、`media-process`、下载记录及历史工作目录只读保留。没有新清单的历史产物不自动认领、续跑或删除；CLUB-494 等既有结果不由本次开发自动重刮或回写。
